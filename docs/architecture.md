# Architecture

## Shape of the repo

```
apps/
  api/          NestJS 11 on Fastify — implements the contract
  web/          Next.js 16 App Router — consumes the contract
  mobile/       README only; not built yet
packages/
  contracts/    Zod schemas + ts-rest contract  ← the only place shapes live
  api-client/   framework-agnostic typed client built from contracts
  auth/         better-auth config (headless)
  db/           Drizzle schema, migrations, seed, typed client
  ui/           design system (cross-platform primitives + web-only)
  design-tokens/ tokens.json → CSS vars, Tailwind preset, RN theme
  config/       shared tsconfig bases
  utils/        pure helpers, no framework imports
infra/docker/   Dockerfiles + compose
```

## How a request flows

```
browser
  │  fetch('/api/backend/users')          same origin → cookie is first-party
  ▼
apps/web  src/app/api/backend/[...path]/route.ts
  │  reads process.env.API_URL at request time, forwards method/headers/body
  ▼
apps/api  UsersController  (@TsRestHandler, validates against the contract)
  │
  ▼      UsersService      (business logic lives here)
  │
  ▼      UsersRepository   (Drizzle queries)
  ▼
Postgres
```

Server Components skip the proxy and call the API directly via
`getServerApiClient()`, forwarding the incoming request's cookies by hand —
the route handler only intercepts real browser requests, not server-side
fetches from within the same process.

## The contract is the hinge

`packages/contracts` defines each route once with Zod. Everything else derives
from it:

| Consumer | How it derives |
| --- | --- |
| `apps/api` | `@ts-rest/nest`'s `tsRestHandler` — request/response validation comes from the contract, so there are no DTO classes and no `ValidationPipe` |
| `/docs` (Swagger) | generated from the contract by `@ts-rest/open-api` |
| `packages/api-client` | `initClient(contract, …)` |
| `apps/web` forms | `zodResolver(createUserInputSchema)` — the *same* schema validates in the browser and on the server |

This is enforced, not just intended: `typecheck` depends on `^build`, so both
apps are checked against freshly built contract types. See
[ADR 0005](adr/0005-typecheck-depends-on-build.md) — before that fix, a
contract rename passed CI green.

## Two kinds of "user"

They are deliberately separate and must not be merged:

- **`user` / `session` / `account` / `verification`** — better-auth's tables,
  generated by its CLI. Identity. Text (nanoid-style) primary keys.
- **`users`** — the example business resource behind `/users`. UUID primary
  key, owned by the app.

Correspondingly `authUserSchema` ≠ `userSchema` in the contracts package.

## Boundaries

Turborepo tags enforce dependency direction (`pnpm boundaries`, run in CI):

- nothing tagged `ui` or `utils` may depend on anything tagged `app`
- `apps/*` may not be imported by `ui`, `utils`, `contracts`, or `db`

Inside `packages/ui`, the cross-platform split is enforced twice: by the module
graph (`@acme/ui/web` is unreachable from the package root) and by a test that
reads the primitive sources and rejects DOM APIs, inline styles, and Radix
imports.

## Modules in apps/api

```
src/
  common/     cross-cutting: exception filter, database module, cookie bridge
  config/     env.ts — Zod-validated, fails fast at boot
  modules/
    auth/     controller + service        (calls better-auth's server API)
    health/   controller + indicator      (pings Postgres)
    users/    controller + service + repository
```

Controllers only translate HTTP ↔ domain; business logic lives in services;
all SQL lives in repositories.

## Build and caching

Every package declares `build` / `lint` / `typecheck` / `test`, wired through
`turbo.json` with `dependsOn` and `outputs` so Turborepo can cache them.

Two packages intentionally have no `build`:

- `@acme/design-tokens` builds via `tokens:build` (Style Dictionary).
- `@acme/ui` ships source — see [ADR 0004](adr/0004-ui-ships-source.md).

`dev` declares `dependsOn: ["^build"]`. Without it, an app's watcher races its
dependencies' first `tsup --watch` pass (tsup cleans `dist/` on start) and the
Nest compiler latches onto that one bad pass with no retrigger.
